# 📐 티스토리 이관 스크립트 프로젝트 구조 검토 문서

본 문서는 티스토리 백업/마크다운 변환 스크립트를 현재 블로그 프로젝트(`blodoc`) 내부에 유지할지, 별도의 독립 프로젝트로 분리할지에 대한 전략적 검토 내용입니다.

---

## ⚖️ 옵션 비교

### 옵션 1. 현재 프로젝트(`blodoc`) 내부 `scripts/`에 유지 (추천)
- **장점**:
  1. **원스톱 개발 & 이관**: 스크립트 실행 한 번으로 `content/posts/` 및 `content/assets/`에 바로 마크다운/이미지가 저장되어 즉시 Next.js 블로그(`npm run dev`)에서 확인 가능.
  2. **맞춤형 파이프라인 유지**: `blodoc`의 옵시디언 마크다운 규격(Frontmatter, 이미지 링크 등) 변경 시 스크립트를 함께 수정하고 관리하기 매우 용이함.
  3. **프로젝트 일치성**: 기존 티스토리 데이터를 `blodoc`으로 완전히 이전하기 전까지 원본 동기화 도구로 편리하게 활용.

---

### 옵션 2. 별도의 파이썬 전용 프로젝트(CLI 도구)로 분리
- **장점**:
  1. **관심사의 분리 (Separation of Concerns)**: Next.js 정적 블로그(TypeScript) 코드베이스와 파이썬 백업 스크립트 의존성이 완전히 분리됨.
  2. **재사용성**: 다른 티스토리 블로그를 백업하거나 타인에게 단순 '티스토리 백업 툴'로 공유/배포하기 쉬움.

---

## 🎯 결론 및 추천 방향

1. **초기/이관 단계**: 현재처럼 `blodoc` 프로젝트 내부의 `scripts/backup_tistory.py`로 두고 이관 작업을 진행하는 것을 추천합니다. 백업 결과가 `content/` 폴더로 바로 들어가므로 이관 결과를 즉시 블로그 런타임에서 테스트하기 편리합니다.
2. **이관 완료 후**: 완전히 티스토리에서 이관을 마친 후 해당 파이썬 스크립트를 독립 툴로 분리하고 싶다면 단일 파이썬 파일(`backup_tistory.py`)을 별도 레포지토리로 옮기면 됩니다.
